# UNAV Pro — Metadata Inspector

When the user selects an object generated by UNAV Pro in Cinema 4D
and clicks **Inspect Selected Object**, the dialog's metadata panel
fills with that object's full astrophysical record. The same panel
feeds the **Copy Metadata JSON** button so the data round-trips out
of C4D into other tools without retyping.

Companion to:

  * `POINT_CLOUD_GENERATION.md` (where the marker container is set
    on each generated null).
  * `NAVIGATION_NULL_SYSTEM.md` (the navigator hierarchy carries the
    same marker container — the inspector reads navigator nodes too).
  * `UNAV_PRO_DATA_PIPELINE.md` §3.8 (the production inspector
    contract this MVP fulfils).

---

## 1. Pieces

| Module                                         | Responsibility                                                |
|------------------------------------------------|---------------------------------------------------------------|
| `unav_pro/core/metadata_lookup.py`             | Pure ``uid → CatalogObject`` index. Loads the bundled sample by default; pluggable for tile-aware loaders later. |
| `unav_pro/ui/metadata_panel.py`                | Reads the selection's marker, queries the lookup, renders display + clipboard text. C4D-bound entry point + pure formatters. |
| `unav_pro/ui/main_dialog.py`                   | Adds the **Inspect Selected Object** + **Copy Metadata JSON** buttons and the multi-line metadata text panel; remembers the last `InspectionResult` between clicks. |

The split is identical to the rest of the plugin: the c4d-bound
surface (selection access, clipboard) is small and gated behind a
``try: import c4d`` guard; the formatting work is pure CPython and
unit-tested without a host.

---

## 2. Data flow

```
User clicks "Inspect Selected Object"
        |
        v
metadata_panel.inspect_active_selection(doc, lookup)
        |
        +-- documents.GetActiveDocument()       -> doc
        +-- doc.GetActiveObject()                -> selection
        +-- _read_marker_from_object(selection)  -> {marker keys}
        |       BC_ID_UNAV_MARKER container off the BaseObject
        |
        +-- core.metadata_lookup.default_lookup()
        |       lazy-loads the bundled sample on first access
        |
        +-- lookup.lookup(marker[MARKER_KEY_UID])
                |
                v
        InspectionResult(status, marker, catalog_object, object_name)
        |
        v
result.display_text  -> SetString(_ID_META_PANEL, ...)
result.status_line   -> appended to the dialog's status log
result.clipboard_json (cached on the dialog for the Copy button)
```

`InspectionResult.status` is one of:

  * `no_doc` — Cinema 4D has no active document.
  * `no_selection` — nothing is selected.
  * `not_unav` — the selected object has no UNAV marker container.
  * `found_marker_only` — marker present but the lookup did not have
    that uid (e.g. the catalog the scene was built from is not in
    the active session). The inspector still renders everything the
    marker carries.
  * `found_full` — both marker and full ``CatalogObject`` available.
  * `no_inspection` — sentinel returned when the user clicks **Copy
    Metadata JSON** before ever inspecting; surfaced as a friendly
    log line.

## 3. UI

The main dialog grows two buttons in the existing 2×N action grid
and one new group beneath the status log:

  * **Inspect Selected Object.** Reads the active C4D selection,
    runs the inspection, sets the metadata panel to
    `result.display_text`, and appends `result.status_line` to the
    log.
  * **Copy Metadata JSON.** Copies the *most recently inspected*
    object's `clipboard_json` payload to the system clipboard via
    `c4d.CopyStringToClipboard`. If the user has not inspected
    anything yet, the dialog logs a friendly nudge instead of
    failing.
  * **Metadata Inspector** group — a `MultiLineEditText` styled
    read-only and monospaced; receives the formatted text. The
    initial placeholder text reads:

    > *Select a UNAV object in the Object Manager and click 'Inspect
    > Selected Object' to view its astrophysical metadata.*

The panel never blocks the C4D event loop: selection access is
synchronous and bounded, the lookup is in-memory, and clipboard
copy is wrapped in a `try/except` boundary handler.

## 4. What gets shown

For a fully-resolved object (`status="found_full"`) the panel
renders four sections, each line aligned for a monospace font:

```
=== UNAV Object Inspector ===
Selection      : Alpha One

--- Identity ---
UID            : sample-star-0042
Catalog source : unav_sample
Object type    : star
Name           : SS-0042
Common name    : Alpha One

--- Astrometry ---
RA  (deg)      : 198.139850
Dec (deg)      : -17.240243
Distance (pc)  : 29.85
Parallax (mas) : 33.5
RV (km/s)      : -24.6
PM (mas/yr)    : RA +12.261, Dec +9.749

--- Photometry ---
Apparent mag   : 3.828
Absolute mag   : 1.454
Color index    : +1.793
Spectral type  : M4I

--- Raw metadata JSON ---
{
  "absolute_magnitude": 1.4536...,
  "apparent_magnitude": 3.8282...,
  ...
}
```

Field-level notes:

  * **Identity.** UID and source are always present. ``Common name``
    only appears when it differs from ``name``.
  * **Astrometry.** Each row appears only if the underlying field is
    populated. The ``PM`` row shows both axes together when either
    is present; the unset axis falls back to 0.
  * **Photometry.** The whole section appears only when at least one
    photometry field is populated (galaxies often have only
    apparent magnitude; spec-only DESI rows have none and skip the
    section entirely).
  * **Raw metadata JSON.** The schema's ``metadata_json`` blob is
    parsed and re-pretty-printed alongside the canonical fields.
    Inline preview is capped at 2 000 characters with a clear
    "truncated; use Copy Metadata JSON for full" footer.

## 5. Marker-only fallback

If the lookup has no matching uid (the user opens a `.c4d` from
months ago and the catalog they built it from is not in the current
session), the inspector falls back to the marker data persisted on
the C4D object itself. That covers:

  * UID, catalog source, object type, name.
  * RA, Dec, distance (when ``MARKER_KEY_DISTANCE_PC`` is non-zero —
    zero is the marker's "no distance" sentinel and is suppressed
    from the display).
  * The schema's ``metadata_json`` blob, parsed for the JSON section.

`status_line` includes the explicit phrase "marker only" so the user
knows the lookup missed and can refresh by re-loading the catalog
that produced the scene.

## 6. Copy Metadata JSON

`InspectionResult.clipboard_json` always contains a self-contained
JSON document:

  * For `found_full`: `CatalogObject.to_dict()` plus a
    `metadata_json_parsed` field that holds the parsed form of the
    schema's stringified blob — so consumers don't have to do the
    second-pass parse themselves.
  * For `found_marker_only`: the marker dict translated to readable
    keys (`uid`, `catalog_source`, …) plus the same parsed metadata
    field.
  * For all other statuses: `{}` — the dialog refuses to copy and
    surfaces a "no metadata to copy" log line.

Clipboard write goes through `c4d.CopyStringToClipboard`. Any
exception is logged and `copy_to_clipboard` returns `False`; the
dialog reports the host refused.

## 7. Robustness rules

The inspector follows the plugin's standing invariants
(`PLUGIN_STRUCTURE.md` §9):

  1. **No exception escapes the C4D boundary.** `Command()` for the
     two buttons is wrapped in a try/except logging-handler.
  2. **Missing data produces messages, not crashes.** Every status
     code has a friendly display text + status line. No active
     document, nothing selected, non-UNAV object, lookup miss, and
     "click Copy without Inspect" are all dedicated paths.
  3. **No top-level c4d import in testable modules.**
     `metadata_panel` guards the import; pure formatters are the
     only thing the unit tests touch.
  4. **Lookup is lazy and forgiving.** `default_lookup()` lazy-loads
     the bundled sample; missing or corrupt sample → empty lookup,
     not an exception.

## 8. Test coverage

`unav_pro/tests/test_metadata_lookup.py` and
`unav_pro/tests/test_metadata_panel.py` between them cover:

  * **Lookup.** uid indexing, membership, sources sorted +
    deduplicated, empty uid rejected, clear resets, loading the
    bundled sample, default lookup laziness + idempotence + reload,
    fallback to empty when the sample is missing,
    `set_default_lookup` override.
  * **Display text.** Each of the five statuses renders cleanly,
    full-record shows every section, marker-only fallback, marker
    `distance_pc=0` is treated as unknown, redshift-only galaxy
    skips PM/parallax, status line variants, no-inspection sentinel.
  * **Clipboard JSON.** Full object includes parsed metadata,
    marker-only translates integer keys to names, empty when no
    data, corrupt `metadata_json` blob does not break the export.
  * **Truncation.** Long raw metadata blobs are truncated in the
    display preview; clipboard payload remains full-fidelity.
  * **C4D guard.** `inspect_active_selection` outside C4D returns
    `no_doc` cleanly; `copy_to_clipboard` returns `False`.

The C4D-bound paths (`_read_marker_from_object`, the actual
clipboard call, the dialog `Command()` plumbing) are exercised by
loading the plugin in Cinema 4D 2023+ — they are not part of the
automated suite.

## 9. Future extensions

Tracked as design intent, not promises:

  * **Cross-source group view.** Production-pipeline uids carry a
    ``match_group_id`` so the same physical object across catalogs
    can be displayed together in the inspector.
  * **Tabbed UI.** The architecture doc envisions tabs (Identity /
    Astrometry / Photometry / Provenance / Raw) instead of a single
    flowing panel. The pure formatters are already structured by
    section so this is mostly a layout change.
  * **Hover-pick.** `BaseDraw` selection callbacks could feed the
    inspector live as the cursor moves over points. Reserved until
    the BaseDraw rendering path lands
    (`POINT_CLOUD_GENERATION.md` §3.2).
  * **Spectroscopy plot.** The DESI / SDSS metadata blobs carry
    line-strength fields that warrant their own renderer. Reserved
    for the metadata inspector dialog spelled out in
    `UNAV_PRO_ARCHITECTURE.md` §3.8.

The MVP shipped here is intentionally one panel and two buttons: it
proves the data path from `BC_ID_UNAV_MARKER` through the lookup to
a human-readable rendering, and that proof is the prerequisite for
every future inspector feature.
